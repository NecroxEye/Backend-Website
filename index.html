One-time backend fixes: missing column, UUID IDs, and two-second triggers

1. Supabase → SQL Editor: add the missing folder column and refresh the schema cache.

alter table public.players
  add column if not exists folder_name text;

notify pgrst, 'reload schema';

2. In server.js: your PUT and DELETE player routes currently convert IDs with Number(req.params.id). UUID IDs become NaN. Replace the ID conversion and numeric validation in both routes with:

const id = String(req.params.id || '').trim();
const validId = /^(?:[0-9]+|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})$/i.test(id);

if (!validId) {
  return res.status(400).json({ error: 'Invalid player id' });
}

// Keep using .eq('id', id).
// Do not convert UUIDs to Number.

3. Two-second trigger delivery must be implemented on the server. In POST /trigger, use expiresAt: now + 2000. In GET /trigger, do not remove a trigger when it is read. Replace the splice read with:

res.setHeader('Cache-Control', 'no-store');

cleanExpiredTriggers();
const trigger = triggerQueue.find(
  t => String(t.computer_name) === computerName
);

return res.json({
  trigger: trigger ? {
    computer_name: trigger.computer_name,
    direction: trigger.direction,
    createdAt: trigger.createdAt,
    expiresAt: trigger.expiresAt
  } : null
});

The computer should remember createdAt and process each trigger only once. Otherwise repeated polling during the two-second window can fire it repeatedly. Two seconds improves delivery, but cannot guarantee receipt if polling takes longer; acknowledgment-based delivery is more reliable. Redeploy server.js after these changes.
